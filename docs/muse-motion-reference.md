# 参考動画から本人のMUSEダンス指示を作る（v395）

「リール制作」の冒頭にある「参考動画から、自分が踊るMUSE指示を作る」を使います。既存の写真切替MP4、20曲の音楽プランナー、汎用MUSEの設定・保存・出力は維持しています。

## 全カットの顔を元画像へ合わせる（v395）

参考動画・音楽から作るダンス・汎用MUSEの全ルートで、各カットの単独コピーに「ORIGINAL PHOTO IDENTITY LOCK」を追加しました。顔の最優先基準は元の本人画像です。目の形と間隔、鼻、唇、頬、顎、輪郭、肌の特徴を保ち、参考動画の人物や前カットの生成顔へ置き換えない指示です。自然な笑顔・まばたき・視線・顔の向きは動かし、表情を固めません。

**CUT 2以降も同じ元の本人画像を毎回添付**してください。前カットの終了画像は姿勢・構図・服・光の接続用です。元画像と顔が一致していると確認できた場合だけ、終了画像を次の開始へ再利用します。顔がずれた画像はそのまま引き継がず、元画像から姿勢を保って修正し、必要なら該当カットの動画も作り直してから接続します。開始・終了キーフレームの指示にも同じ優先順位を入れています。

複数の本人参照がある場合、先頭の元画像を主基準とし、別人の顔を混ぜません。画像を1枚しか渡せない画面では、元画像から用意し、顔の一致を確認した開始画像を使います。プロンプトは顔の維持を指示するもので、MUSE出力の完全な一致や自動の顔照合を保証する機能ではありません。

## 操作

1. 参考動画（MP4/MOV、150MB・10分以内）と本人画像（1枚15MB以内）を選びます。既存MUSE欄の本人画像も取り込めます。
2. 動画の開始位置と、2〜30秒の使用区間を指定します。仕上げ尺はその区間と同じです。動画を再生しながら開始位置を合わせられます。
3. 「区間のコマ・テンポを準備」で0.5秒ごとの参考画像を最大60枚抽出し、音声からBPM・拍を端末内で推定します。
4. 参考画像のOpenAI送信への同意をチェックし、「AIで画角・振付・表情を読み取る」を押します。OPS所有者のログインと既存のOpenAI接続が必要です。画像入力・テキスト出力のAPI利用料が発生します。自動の再試行・別モデルへの切替は行いません。
5. 秒数別の画角、体・腰・肩、左右の手と指、足、顔の向き、目線、表情、加減速を確認し、必要なら英語欄や時刻を補正します。BPM・拍位置も手修正できます。AIを使わず、動画を見て動きの区間を手入力することもできます。
6. 「0.5秒刻みのMUSE制作指示を作る」で英語のCUT別指示、キーフレーム指示、ChatGPTへの引き継ぎ、編集手順を出力します。
7. 本人画像と画像作成指示をChatGPT等へ手動で添付し、本人が開始・終了姿勢をとる9:16画像を1枚ずつ用意します。開始画像と該当CUTの英語指示をMUSEへ渡します。前CUTの終了画像を次CUTの開始画像に再利用します。
8. CUT順に動画編集アプリで結合し、元動画と同じ速度・音楽のフレーズに合わせます。本人画像と指示書の保存・対応端末でのファイル共有も利用できます。

## バズりモードとキャプション（v394）

冒頭の「バズりモードとキャプションへ」から設定へ移動できます。

- **参考の再現を優先**：これまでの振付・画角・表情とタイミングを基準にします（初期値）。
- **かわいく映える**：参考にある目線・表情や自然なスカートの揺れを見やすくする演出案を、CUTのMUSE指示へ追加します。
- **ダイナミックに魅せる**：参考にある動作の切り返し・重心移動・足の接地を明瞭に見せる提案を追加します。

演出案は観測した動作と別の見出しに記載します。参考の秒数、0.5秒チェックポイント、1.0倍速度、左右、振付、画角順、衣装・人物の同一性を優先します。新しいダンス動作やカメラ移動を追加しません。「バズり」は演出の提案名で、再生数の保証ではありません。ループ編集は実際の開始・終了姿勢がつながる場合だけ提案します。

キャプションは「Instagram／Threads」「甘め／小悪魔／上品」「おまかせ／ダンス／コーデ／笑顔」を選び、任意のひと言を入力して「かわいいキャプションを作る」を押します。動画・ログイン・AI解析なしでも、端末内の文章テンプレートから3案を作れます。追加のAPI利用料はかかりません。

3案から1つを選び、その場で編集・コピー・テキスト保存できます。「別の3案を見る」で候補を変えられます。Instagram案には3〜4個の関連タグ、Threads案にはタグを付けません。手入力が投稿先の文字数を超える場合はコピー前に案内します。短い冒頭テロップ案も編集・コピーでき、映像には動画編集アプリで後付けします。文字をMUSEの映像へ描かせる指示は出しません。

動画の指示作成時にもキャプションを用意します。既に編集した本文・テロップは指示書を再作成しても保持します。制作指示書の保存・共有には、選んで編集した文章も含まれます。本人のひと言は投稿欄の文章だけに入り、MUSEやChatGPTへ渡す英語指示には混ぜません。実際の映像と合う文章へ整えて投稿してください。

## 0.5秒・音楽・スカートの詳細

各CUTには0.5秒ごとのチェックポイントを含め、完成動画内・CUT内・元参考動画内の秒数を併記します。末尾だけ0.5秒未満になる場合があります。0.5秒は拍の長さとは別です。元の再生速度1.0倍と動作時間を維持し、拍へ勝手に動作を移動したり、各行ごとに同じ動きを繰り返したりしない指示を出します。

「スカートの裾を自然にヒラヒラ」は初期ON。ステップや腰の向きに少し遅れて裾が動き、慣性・重力・減衰に従って収まる演出です。裾丈・服の形・不透明さを維持し、浮き続ける布や不自然な風、脚へのめり込み、裾の捲れを避けます。パンツをスカートへ変更しません。

BPM・拍は推定または手入力として表示し、強拍・小節頭の正しさやMUSE出力の完全同期は保証しません。無音・不規則な音声や解析できない場合はBPMを作らず未確認にします。iPhoneのメモリ負荷を抑えるため、2分を超える元動画では音声解析を省略します。短く切り出した動画や手入力BPMを利用できます。

## データと実装

- 元動画、音声、本人画像は端末内のメモリのみで扱い、クラウドへ保存しません。本人画像・動画・音声を新APIへ送ることはありません。
- 同意とAI解析ボタンの操作がそろったときだけ、選択区間の低解像度JPEGコマと時刻を既存Supabase経由でOpenAI Responses APIへ送ります。`store:false`を指定し、OPSのStorage・DBには保存しません。OpenAI側の監視ログ等まで保存ゼロを保証するものではありません。
- 新Edge Function `muse-motion-analyze` はJWT有効・所有者照合・JSON総量5MB・各画像の型/寸法/サイズ・時刻/出力の検証を行います。外部URLや本人画像フィールドを受け付けません。
- OpenAIキーは既存の `hanako_openai_key_read`、`OPENAI_API_KEY` 等を再利用します。追加の有料サービスは不要。任意の `MUSE_MOTION_MODEL`、次いで既存 `OPENAI_TEXT_MODEL` を使い、未設定時は既存OPSと同じ `gpt-5.5` です。クライアントにキーを埋め込みません。
- 純粋な指示生成は `muse-motion-engine.mjs`、端末内メディア処理は `muse-motion-media.mjs`、画面は `muse-motion.mjs` に分離しています。DB変更はありません。

## 確認できる範囲

0.5秒の静止コマはフル動画解析ではありません。速い振付、隠れた足・指、フレーム間の動きは未確認または推定として扱います。入力にない動作はUNKNOWNとして残し、公式振付や完全再現と断定しません。元映像のフレーム境界まで正確なシークを保証するものでもありません。

MUSEの生成尺・開始/終了画像・参照動画・音声の入力機能は利用環境により異なります。出力では5秒以内のCUTを計画しますが、利用画面がその尺をサポートすると断定しません。非対応なら開始画像と文章を使い、長い出力を後編集します。この機能はMUSEへの自動送信や動画の結合・投稿を実行しません。

公式仕様の確認元： [OpenAIの画像入力ガイド](https://developers.openai.com/api/docs/guides/images-vision?api-mode=responses)、[MetaのMuse Image / Video発表](https://ai.meta.com/blog/introducing-muse-image-muse-video-msl/)。
