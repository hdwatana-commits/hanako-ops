# 曲と写真から作るMUSE指示

Instagram → リール自動制作 → MUSE制作の「曲と写真から、雰囲気リールの指示を作る」。曲検索・20曲選択、本人写真、演出おまかせで制作セットを作る。7/10/15/20/30秒、6演出、0.5秒単位の動作表、英語カット別コピー、オリジナルキャプション、指示書・画像保存と対応端末での共有。

画像の変換と制限は既存prepareAsset（15MB、最大1800px、JPEG変換）を再利用。この簡単モードに添付した写真は画面のメモリ内のみ。既存MUSE欄の本人写真は再利用可能。外部送信・有料API・DB・新環境変数はない。MUSEへの画像添付・動画生成・Instagram音楽追加・公開は手動。

6演出は公開リールの部分観察を参考にした編集上のオリジナル提案。各アカウント20本ずつの全編検証や公式振付抽出を完了したものではない。元画像の顔・髪・服・背景を優先し、写真だけでは読めない隠れた足運びは指定しない。7秒は1カット、長尺は5秒ずつ。出力尺はサービス画面と結果で確認。顔の同一性・振付再現・完全同期は保証しない。

初期20曲は既存カタログを再利用し、現在のInstagram人気ランキングとは表示しない。話題性の根拠を確認できた3曲は、UIに出典を表示する（確認日2026-11-06）。

- わたしの一番かわいいところ：Billboard JAPAN 2022年記事 https://www.billboard-japan.com/d_news/detail/113631/2
- イイじゃん／倍倍FIGHT!：MUSIC AWARDS JAPAN 2026 バイラル部門候補資料 https://www.musicawardsjapan.com/2026assets/pdf_num/21.pdf

適合する演出は曲のmovementFamilyから選ぶ編集提案であり、音声解析結果ではない。音源開始・BPMは未確認のまま空欄。入力した数値もユーザー目安として扱い、測定した拍やサビと混同しない。音源・歌詞を取得せず、曲名を指定してモデルに既存楽曲を生成させない。実音源解析には既存「音楽からダンスを作成」を使う。

検証：node --test tests/*.test.mjs、node --check app.js、node --check muse-song-vibe.mjs。写真準備は既存コードを利用する。iPhone実機と実際のMUSE出力は別途確認が必要。

## v404：40本の参考登録

40本の動画別参照データ、7分類、候補曲、元の長さ、元音源表示、時刻付きの日本語・英語の観察点を追加。詳しい確認方法と一覧は [40本の観察記録](reels-40-observations.md) を参照。元尺・短尺で元の動画内時間を保ち、長尺の余りは静止として指示する。動作の経路は推定補間で、連続映像全フレームや音楽同期の検証ではない。

## v408：小刻みに腰を揺らす

参考を選んだ後、「腰の動き」で「小刻みに腰を揺らす」を選択。初期値は追加なし。元の動作順・尺・顔・衣装・手振りを保つ追加演出で、観察された振付とは区別する。立ち姿で腰が見える場合に小さな左右の揺れを加え、座り・見切れ・回転やバランスが必要な場面では抑制。過度な腰振り、体形変化、強い反り、衣装の変形を禁止。スカートは既存の服だけ自然に揺らし、裾を持ち上げず、パンツにスカートを追加しない。

0.5秒の各行に全体時刻による位相と振幅を出力し、CUT境界でリズムをリセットしない。冒頭0.5秒と有効区間の末尾0.5秒で弱める。BPM未指定時の1秒一往復は編集上の目安。入力BPMがある場合は2拍一往復とし、解析済みの曲同期とは表示しない。参考尺を超えた余白に揺れを追加しない。動画生成はMUSE側での結果確認が必要。
